# 营业收入卡片与图表高亮联动 实现记录

> 组件路径：`src/views/kongguJww/smartTechnology/components/homeIndex/DownComp.vue`

## 一、需求

营业收入下钻页由「上行 6 张品牌卡片 + 下行 2 张图表」组成。要求：

1. `activeIndex` 对应的卡片显示 `#004567` 高亮边框。
2. 下方两张图表同步显示 `#004567` 边框，与选中卡片视觉上连成**一个闭合外框**。
3. 卡片与图表之间有 **20px 间隙**，选中态用竖线跨过间隙把上下连起来。
4. **连接处不能出现横向的边框分割线**（卡片底边 / 图表顶边那一行要"擦掉"）。

## 二、当前实现

### 2.1 结构

```
.down-comp
├── .card-row                    // 6 张卡片，flex + gap: 16px，每张 flex: 1
│   └── .card-item[.card-item--active]
├── .seam                        // 20px 间隙 + 连接竖线
│   └── .seam-cell[.seam-cell--active] × 6
└── .chart-section[.chart-section--active]
    ├── .chart-item--top         // 营收整体趋势
    └── .chart-item--bottom      // 竞品对比
```

### 2.2 三段样式的职责

**卡片**：只负责自己的边框。底边设为 `transparent` 而不是 `none` —— 保留 1px 占位让盒子高度不跳动，同时该行不出现横向分割线。

```scss
.card-item.card-item--active {
  border-bottom-right-radius: 0;
  border-bottom-left-radius: 0;
  border-color: #004567;
  border-bottom-color: transparent;
}
```

**连接件**：`.seam` 的 flex 结构与 `.card-row` **逐项对应**（同样的 `gap`、同样 6 格、每格同样 `flex: 1`），因此两行的格子边缘由浏览器用同一套弹性分配算出。竖线画在选中格上，天然对齐上方卡片的边框。

```scss
.seam {
  display: flex;
  position: relative;
  z-index: 2;
  height: calc(20px + 1px);   // +1px 用于上移后仍保持 20px 净间距
  margin-top: -1px;           // 上移盖住卡片底边那一像素行
  gap: 16px;
  pointer-events: none;
}

.seam-cell { flex: 1; min-width: 0; }

.seam-cell--active {
  position: relative;

  &::before {                 // 两条竖线
    content: '';
    position: absolute;
    box-sizing: border-box;
    inset: 0;
    border-right: 1px solid #004567;
    border-left: 1px solid #004567;
  }

  &::after {                  // 遮掉图表顶边中间那一段
    content: '';
    position: absolute;
    top: 100%;
    right: 0;
    left: 0;
    height: 1px;
    background: #fff;
  }
}
```

**图表区**：选中态整块同步高亮。选择器用 3 层 class 提权，压过 `.chart-item--bottom > .key-trend-card` 自带的 `#cedff0`。

```scss
.chart-section--active .chart-item :deep(.key-trend-card) {
  border-color: #004567;
}
```

### 2.3 两个容易踩的细节

**竖线不能直接加在 `.seam-cell` 上。** 带边框的 flex 项（`flex-basis: 0` + `border-box`）宽度以边框宽为下限，选中格会比同排其他格宽 2px，反而把对齐好的边缘又推歪。用绝对定位的伪元素画线，伪元素脱离文档流，六格分配保持完全一致。

**遮挡条的宽度不用手写。** `left/right: 0` 即 `.seam-cell` 的 padding box 左右沿，正好是两条竖线的内侧，宽度天然吻合。

## 三、排查过程

这个问题改了 5 轮，每轮的失败原因都不同，记录下来避免重走。

### 第 1 轮：高亮完全不生效

原始代码：

```scss
.card-item.card-item--active :deep(.card-comp) { border-color: #004567 !important; }
```

`class="card-item"` 落在 `SortCardItem` 的**根元素**上，而根元素本身就是 `.card-comp`（`sortCardItem.vue:2`）。后代选择器要求 `.card-comp` 是 `.card-item` 的子孙，但两者是**同一个元素**，所以永远匹配不到 —— 加 `!important` 也没用。

> 教训：给组件传 class 时，先确认它落在根元素还是内部元素上。落在根元素时要直接写在该 class 上，不能用后代选择器。

同轮还发现竞品对比卡上有内联 `border-bottom: none`，会让高亮方框底边缺一条，已移到 scoped 样式里。

### 第 2 轮：首/末张没有连接线 + 垂直错位

第 2 轮把竖线做成**卡片的伪元素**，靠 `left: -1px; right: -1px` 向外扩 1px 去对齐卡片边框。结果：

- **首张卡片左侧、末张卡片右侧的线消失** —— 首张贴容器左缘、末张贴右缘，外扩的 1px 被祖先的 `overflow: hidden` 裁掉了。中间几张不贴边所以看着正常。
- **垂直错位、横线没擦掉** —— 白条用 `top: calc(100% + 20px + 1px)` 这种链式偏移去"猜"图表顶边的位置，任何一处 1px 假设不成立就整体偏移。

### 第 3 轮：JS 实测几何 —— 被 scale 破坏

改成用 `getBoundingClientRect()` 量取卡片位置，写进 `margin-left` / `width`。错位更明显了。

**根因**：本页整体套在 `WidthScaleContainer` 里，`design-width: 1920`，屏幕层挂了 `transform: scale(可用宽度 / 1920)`（`WidthScaleContainer.vue:79`，入口在 `modules/smartTechnology/Entry.vue:13`）。

- `getBoundingClientRect()` 返回**缩放后的视口像素**
- `margin-left` / `width` 写回去时在**缩放前的布局坐标**里解析

两者相差 `1/scale`。1920 设计稿在 1536px 宽窗口下 scale ≈ 0.8，量出来的偏移直接短 20%，且越靠右误差累积越大。

> 教训：**在 `transform: scale` 容器内，绝不能把 `getBoundingClientRect` 的结果写回布局属性。** 这是本次最关键的一条。

### 第 4 轮：CSS 百分比 —— 亚像素取整

改成纯 CSS 百分比推算，绕开了 scale 换算问题（百分比在布局坐标内解析，与卡片一起被同一个 transform 缩放）：

```scss
--card-width: calc((100% - (var(--card-count) - 1) * 16px) / var(--card-count));
margin-left: calc((var(--card-width) + 16px) * var(--seam-index));
```

大部分情况对了，但**有时**连接处看着不是一条线。

**根因**：卡片实际宽度不是这么算的 —— `.card-item` 是 `flex: 1`，浏览器走**弹性空间分配**，有自己的余数处理（除不尽的部分摊到某几格上）。手算均分值与 flex 实际分配只是**近乎**相等，差值通常不到 1px。scale = 1 时肉眼不可见；带非整数缩放比时，亚像素差值乘上 scale 后可能跨过取整边界，落到相邻像素列 —— 于是竖线错开一点。取决于窗口宽度算出的 scale 恰好落在哪里，所以是"有些时候"。

### 第 5 轮（当前）：复刻 flex 结构

不再手算，直接让浏览器算两遍：`.seam` 复刻 `.card-row` 的 flex 结构，两行走同一套弹性分配和同一套亚像素取整，格子边缘落在同一列像素上。

同时删掉了 JS 侧不再需要的 `seamStyle`、`measureSeam()`、`cardRowEl` ref 和 `ResizeObserver` —— 纯 CSS 方案跟着布局走，不用监听。

## 四、遗留问题

**当前版本在非整数 scale 下仍能看到细微错位。**

第 5 轮之后还尝试过一版「把竖线挂回选中卡片的伪元素、靠卡片自身 border box 定位」，理由是这样竖线位置直接从卡片盒子推导，不存在两个独立盒子各自取整。但该版本经确认仍有错位，**已回滚**，当前保留的是第 5 轮的 `.seam` 方案。

回滚时**没有用 `git checkout`** —— 该文件同期还有品牌下拉框弹层定位的改动（`brand-select-wrap` 包裹层、`popupClassName`、`getOwnBrandPopupContainer`），整文件回退会一起丢掉，所以做的是定向撤销。

### 下一步建议

问题本质是「两个独立绘制的 1px 边框在非整数缩放下必须落在同一列设备像素」，这在 CSS 层面很难保证。可考虑的方向：

1. **取消间隙**，让卡片与图表直接相邻（`margin-top: -1px` 重叠），只需一条边框，从根上没有对齐问题 —— 需设计确认是否接受。
2. **整体改用一个外框元素**：把「选中卡片 + 图表区」包在一个带边框的容器里，用遮挡条挖出卡片之间的缺口，边框始终只有一个盒子。
3. 让 `WidthScaleContainer` 的 scale 取整到 0.5 的倍数，牺牲一点填充精度换取像素对齐。

### 复现与验证

本仓库无 Playwright / Puppeteer，无法自动截图验证像素级效果。排查时建议直接提供：

- DevTools 里 `.card-item--active` 与 `.seam-cell--active` 的 computed width，以及当时的 scale 值（`window.innerWidth / 1920` 的实际取值）

## 六、经验小结

1. 给组件传 class 前，先确认它落在根元素还是内部元素 —— 决定用不用后代选择器。
2. **在 `transform: scale` 容器内，`getBoundingClientRect` 的值不能写回布局属性**，两者不在同一坐标系。
3. 手算的均分宽度 ≠ `flex: 1` 的实际分配，差值在缩放场景下会被放大成可见错位。想和 flex 对齐，就复刻 flex 结构，别手算。
4. 带边框的 flex 项（`flex-basis: 0` + `border-box`）宽度以边框宽为下限，会挤歪同排其他项 —— 装饰性边框用绝对定位伪元素画。
5. 无法自己截图验证时，纯靠推理调 1px 偏移的效率很低。应尽早索取渲染反馈（截图 / computed 值），而不是连续换方案试。
