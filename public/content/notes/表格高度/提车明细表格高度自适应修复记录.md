# 提车明细表格高度自适应修复记录

日期：2026-11-05
涉及组件：`apps/smart-technology/src/views/kongguJww/smartTechnology/components/salesDetail/VehicleDetail.vue`（国内/国际营销明细页的"销量指标-提车明细"表格）

## 1. 问题现象（按排查过程）

1. 表格高度很小，只占屏幕一半左右，`window.addEventListener('resize', updateBodyScrollY)` 看起来完全不生效；
2. 窗口缩小后再放大，表格高度比操作前更高，缩放前后不一致；
3. 窗口高度变化后，表格高度与正常加载时展示不一致；
4. 表体内容不满一屏时纵向滚动条也常驻显示。

## 2. 环境背景

该页面运行在三层结构之下，三个问题根源分别来自其中一层：

```
宿主应用（wujie 微前端）
  └ WidthScaleContainer（大屏适配：内容按 transform: scale(容器宽/1920) 等比缩放）
      └ 页面（.smart-box-header 面包屑/筛选 + .smart-box-container 内部滚动容器，
             容器内表格下方还有趋势图、线索明细等区块）
```

## 3. 问题根源

### 3.1 wujie 隐藏 iframe：`window.innerHeight` 恒为 0

wujie 沙箱 iframe 以 `style: "display: none"` 创建（wujie-core `iframe.js`），隐藏 iframe 视口为 0，子应用里 `window.innerHeight` 恒为 0，导致
`available = 0 - rect.top - buffer` 永远为负、`bodyScrollY` 永远落在兜底值 160——表格只剩约半屏高。

`resize` 事件不在 wujie 的 window 事件白名单内（仅 `hashchange/popstate/load/message` 等，见 wujie-core `common.js` 的 `appWindowAddEventListenerEvents`），监听实际被挂到宿主 window：浏览器缩放时回调有执行，但 `innerHeight` 恒为 0，算出的结果不变——表现为"resize 没生效"。

### 3.2 缩放容器：视觉像素与设计像素混算 + scale 重算时序

- `getBoundingClientRect()` 返回的是**视觉像素**（已乘 scale），而 `scroll.y` 作用在缩放容器内部的**设计像素坐标系**上，两者直接混算在 `scale ≠ 1` 时本身就不准；
- `WidthScaleContainer` 用 ResizeObserver + requestAnimationFrame **延迟一帧**重算 scale，resize 当帧 transform 还是旧值：窗口放大时量到旧的小 scale → `rect.top` 偏小 → 高度算大；scale 随后更新但没有新事件来纠正，误差留存——"缩小再放大后表格变高"；
- 缩放比按宽度算（`容器宽/1920`）且容器 `fill-parent-height`：窗口缩窄时设计坐标系里的可视高度反而变大，"每次填满视口"的策略下表格会越缩越高。

### 3.3 测量基准错误：视口底不是填充边界，且测量依赖滚动位置

- 页面真正的内容边界是内部滚动容器 `.smart-box-container` 的可视区底（容器内表格下方还有趋势图/线索明细区块，容器底边也高于视口底），以视口底填充会溢出；
- `getBoundingClientRect().top` 随容器滚动位置变化，滚动后测量会虚大。

### 3.4 antd：`scroll.y` 强制滚动条常驻

antd-vue 4.2.6 收到 `scroll.y` 后把表体写死 `overflow-y: scroll`（`vc-table/Table.js:182`），内容不满一屏滚动条也显示。

## 4. 修改方案（最终实现）

### 4.1 测量：全部基于滚动容器布局像素，与缩放、滚动无关

```ts
function updateBodyScrollY() {
  const el = tableWrapRef.value;
  if (!el) return;
  const scrollContainer = el.closest<HTMLElement>('.smart-box-container');
  if (!scrollContainer) return;
  // 已应用缩放比 = 缩放元素视觉宽 / 布局宽（transform 不改布局值，任何时刻自洽）
  const screen = el.closest<HTMLElement>('.width-scale-container__screen');
  const appliedScale =
    screen && screen.offsetWidth > 0 ? screen.getBoundingClientRect().width / screen.offsetWidth : 1;
  // 表格顶边在滚动容器内容里的设计坐标：rect 差值除以缩放比，再加回 scrollTop 抵消滚动
  const tableTopInContainer =
    (el.getBoundingClientRect().top - scrollContainer.getBoundingClientRect().top) / appliedScale +
    scrollContainer.scrollTop;
  const headerHeight = el.querySelector<HTMLElement>('.ant-table-thead')?.offsetHeight ?? 0;
  const available =
    scrollContainer.clientHeight - tableTopInContainer - headerHeight - SCROLL_Y_BOTTOM_BUFFER;
  bodyScrollY.value = available > SCROLL_Y_MIN_HEIGHT ? available : SCROLL_Y_MIN_HEIGHT;
}
```

要点：

- **填充边界**改为 `scrollContainer.clientHeight`（布局像素，定高 `calc(100% - 88px)`），不再依赖 `window.innerHeight`，彻底绕开 wujie 隐藏 iframe 的问题；
- `clientHeight` / `offsetHeight` 是布局像素，天然不受 `transform: scale` 影响，无需区分"已应用 scale / 即将生效 scale"，也就没有 scale 重算时序问题；
- 表格顶边用「rect 差值 ÷ appliedScale + scrollTop」换算成内容坐标，**滚动前后、缩放前后量出的都是同一个值**（幂等），与正常加载展示一致；
- 表头高度一并扣除（`scroll.y` 只约束表体，表头吸顶在表体上方）。

### 4.2 触发：ResizeObserver 观察滚动容器，替代 window resize

```ts
scrollResizeObserver = new ResizeObserver((entries) => {
  const { width, height } = entries[0].contentRect;
  const box = `${width}x${height}`;
  if (box === lastContainerBox) return;          // 尺寸去重
  lastContainerBox = box;
  if (scrollRafId) cancelAnimationFrame(scrollRafId);
  scrollRafId = requestAnimationFrame(() => {    // rAF 延迟，避开 RO 通知阶段同步改 DOM
    scrollRafId = 0;
    updateBodyScrollY();
  });
});
scrollResizeObserver.observe(scrollContainer);
```

- 窗口高度变化 / 全屏切换 / 缩放比重算最终都会体现为容器的布局高度变化，RO 比 window resize 覆盖更全、触发时布局已稳定；
- 数据刷新后（`watch(() => tableData.value.length, …, { flush: 'post' })`）DOM 更新完成再补量一次；
- **无死循环**：容器高度是定高（上级链路全部定高 + `overflow: hidden`），表格内容高度变化被 `overflow-y: auto` 内滚吸收，不会回灌到被观察的盒子；回调按本仓库 RO 惯例（BizDataChart / useECharts 等）做 rAF 延迟 + 尺寸去重，卸载时 `cancelAnimationFrame` + `disconnect`。

### 4.3 滚动条：内容放得下时不下发 `scroll.y`

```ts
const TABLE_ROW_HEIGHT = 40; // CockpitTable 表体 td 固定行高

const tableScrollY = computed(() => {
  const y = bodyScrollY.value;
  if (y === undefined) return undefined;
  return tableData.value.length * TABLE_ROW_HEIGHT > y ? y : undefined;
});
```

antd 只要收到 `scroll.y` 就强制 `overflow-y: scroll`。改为：行总高 ≤ 可用高度时**不传** `scroll.y`——表体不限高自然铺开，无滚动条；超出才下发，表体限高内滚、表头吸顶、滚动条按需出现。CSS `!important` 覆盖 antd 内联样式的方式不可靠，故弃用。

## 5. 解决的问题

| 现象 | 根源 | 对应方案 |
| --- | --- | --- |
| 表格只占半屏、resize "不生效" | wujie 隐藏 iframe `innerHeight` 恒为 0 | 不再读视口，以滚动容器 `clientHeight` 为边界 |
| 缩小再放大后表格变高 | rect 视觉像素与设计像素混算 + scale 延迟重算时序 | 布局像素测量，scale 只做 rect 差值换算且任何时刻自洽 |
| 窗口高度变化后展示不一致 | 以视口底为边界 + 测量依赖滚动位置 | 以滚动容器可视区底为边界，顶边换算抵消 scrollTop，测量幂等 |
| 滚动条常驻 | antd `scroll.y` 强制 `overflow-y: scroll` | 内容放得下不下发 `scroll.y` |

## 6. 涉及文件

- `apps/smart-technology/src/views/kongguJww/smartTechnology/components/salesDetail/VehicleDetail.vue`——全部修改集中于此（测量逻辑、ResizeObserver、tableScrollY computed）；
- 未改动 `CockpitTable.vue`、`WidthScaleContainer.vue` 及 wujie 相关配置，不影响其他使用方。

## 7. 经验小结

- wujie（iframe 沙箱）子应用里不要信任 `window.innerHeight / innerWidth / resize`：隐藏 iframe 视口为 0，且 resize 不在事件白名单；需要视口信息时用 `el.ownerDocument.defaultView`（宿主 window），或尽量改为容器布局测量；
- `transform: scale` 缩放容器内：`getBoundingClientRect()` 是视觉像素，布局值（`clientHeight/offsetHeight/scrollTop`）是设计像素，混算必错；缩放组件若延迟重算 scale，resize 当帧的 rect 不可信，优先用纯布局值推导；
- 表格自适应高度时，填充边界应是"最近的内部滚动容器可视区"，不是浏览器视口；
- antd 表格 `scroll.y` 有"滚动条常驻"副作用，按需内滚可通过"放得下就不传 scroll.y"实现。
